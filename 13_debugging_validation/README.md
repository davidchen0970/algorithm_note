## Part 13　實作、除錯與驗證

### 這一 Part 在做什麼

這一 Part 關注從正確想法到可靠程式之間的落差。許多錯誤不是演算法方向有誤，而是介面、邊界、更新順序、型別、生命週期或測試不足。這裡會建立可重複的實作與排查流程，讓 Debug 聚焦在第一個不符合預期的狀態。

### 學完後應該能做到

- 把演算法步驟轉成清楚的程式結構
- 辨認常見 Boundary、State、Pointer 與型別錯誤
- 建立最小失敗案例與逐輪追蹤方式
- 使用量測資料進行效能分析與改善

### 建議閱讀方式

- 先建立實作方法，再整理常見 Bug。
- 除錯流程與效能改善應以可重現資料為基礎。

### 閱讀時可以反覆問自己

- 這個主題要解決哪一類問題？
- 它成立需要哪些前提？
- 目前維護的 State 或 Invariant 是什麼？
- 如果條件改變，原方法是否仍然成立？
- 時間與空間成本主要來自哪裡？
