# 第 2 章　時間複雜度與空間複雜度

## 適用範圍

本章說明如何估算演算法隨輸入規模增長所需的時間與額外記憶體，涵蓋 Big-O、Big-Theta、常見成長階、最好與最差情況、攤銷分析、遞迴成本，以及如何從 Constraint 反推可接受解法。

## 適用讀者

- 已能閱讀基本迴圈、函式與 C++ 容器的讀者。
- 面對多個解法時，不確定如何比較效率的讀者。
- 容易只看巢狀迴圈層數，忽略總移動量、複製與容器成本的讀者。

## 2.1 複雜度在描述什麼

令 `n` 代表輸入規模。複雜度描述 `n` 增長時，執行步驟或額外空間如何成長。它不是精確秒數，也不包含所有硬體差異，但能排除成長速度不合理的方案。

- `O(f(n))`：漸進上界。
- `Ω(f(n))`：漸進下界。
- `Θ(f(n))`：上下界同階。

一般解題文件常以 Big-O 表示最壞情況上界，但必須註明平均、最差或攤銷語意。

## 2.2 常見成長階

```text
O(1)       固定次數工作
O(log n)   每一步按比例縮小候選
O(n)       完整走訪一次
O(n log n) 常見於高效率比較排序
O(n²)      枚舉 Pair 或二維狀態
O(2^n)     枚舉 Subset
O(n!)      枚舉 Permutation
```

忽略常數與低次項是因為大型 `n` 時最高階項主導成長：

```text
3n + 20       → O(n)
n² + 100n    → O(n²)
```

這不表示常數不重要。兩個同為 `O(n)` 的程式仍可能因 Cache、配置記憶體與分支行為有明顯差異。

## 2.3 分析迴圈

### 2.3.1 單層迴圈

```cpp
long long sum(const std::vector<int>& nums)
{
    long long answer = 0;
    for (int value : nums)
    {
        answer += value;
    }
    return answer;
}
```

每個元素處理一次，時間 `O(n)`，額外空間 `O(1)`。

### 2.3.2 獨立階段相加

兩個先後執行的 `O(n)` 迴圈是 `O(n+n)=O(n)`，不是 `O(n²)`。

### 2.3.3 巢狀迴圈不一定是平方

```cpp
int right = 0;
for (int left = 0; left < n; ++left)
{
    while (right < n && condition(left, right))
    {
        ++right;
    }
}
```

如果 `right` 全程只從 `0` 增加到 `n`，內層總執行次數為 `O(n)`。分析時要看所有迭代的總工作量，而不是只數語法層數。

## 2.4 分析容器與函式

常見隱藏成本：

- 傳值接收 `vector` 或 `string`：通常複製 `O(n)`。
- `std::sort`：`O(n log n)`。
- `std::map` 查找：`O(log n)`。
- `std::unordered_map` 查找：平均 `O(1)`。
- Priority Queue Push/Pop：`O(log n)`。
- `string::substr`：通常建立長度相關的副本。

```cpp
void solve(std::vector<int> nums)
{
    std::sort(nums.begin(), nums.end());
}
```

這段包含參數複製 `O(n)` 與排序 `O(n log n)`，整體仍為 `O(n log n)`。

## 2.5 空間複雜度

空間複雜度通常分析額外空間：

- 固定數量變數：`O(1)`。
- 和輸入等長的結果 Array：`O(n)`。
- `n × n` DP Table：`O(n²)`。
- 深度 `n` 的遞迴 Stack：`O(n)`。

原地演算法通常表示只使用固定或少量額外空間，不代表輸入本身不占空間。

## 2.6 遞迴與攤銷分析

### 2.6.1 遞迴樹

Merge Sort：

```text
T(n) = 2T(n/2) + O(n)
```

每層合併總工作 `O(n)`，共有 `O(log n)` 層，因此時間 `O(n log n)`。

### 2.6.2 重複子問題

暴力 Fibonacci 會反覆計算相同 `F(k)`，時間呈指數成長。Memoization 讓每個狀態只計算一次，降為 `O(n)`。

### 2.6.3 攤銷成本

`std::vector::push_back` 偶爾 Reallocate，該次可能為 `O(n)`；容量按比例增長時，多次追加的平均成本為攤銷 `O(1)`。

## 2.7 從 Constraint 選解法

粗略判斷：

| 輸入規模 | 常見可評估方向 |
|---:|---|
| `n <= 10` | Permutation、完整搜尋 |
| `n <= 20` | `O(2^n)`、Bitmask DP |
| `n <= 1000` | 部分 `O(n²)` |
| `n <= 100000` | `O(n log n)` 或 `O(n)` |
| 更大 | 線性、對數或數學方法 |

這是篩選工具，不是執行時間保證。還要考慮常數、測資數量與語言成本。

## 2.8 常見問題與判讀

| 現象 | 常見原因 | 第一輪檢查 |
|---|---|---|
| 估成 `O(n²)` 但實際是線性 | Pointer 總移動量未計算 | 每個 Pointer 最多移動幾次 |
| 遞迴記憶體超限 | 忽略 Call Stack | 最大遞迴深度 |
| Hash 解法被寫成最差 `O(1)` | 混淆平均與最差 | 容器複雜度語意 |
| 明明只有一個迴圈卻很慢 | 迴圈內發生複製或排序 | 函式與容器成本 |
| 小輸入最佳化後反而慢 | 常數與配置成本 | 實測與輸入範圍 |

## 2.10 本章重點

1. 複雜度描述成長速度，不是精確執行秒數。
2. 巢狀語法不必然代表相乘，要分析總工作量。
3. 容器複製、排序與查找都必須納入成本。
4. 遞迴時間與 Call Stack 空間需要分開分析。
5. Constraint 是選擇演算法的重要輸入。
