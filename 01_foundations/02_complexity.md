# 第 2 章　時間複雜度與空間複雜度

## 適用範圍

本章說明如何描述演算法需要的工作量與額外記憶體，以及為什麼不能只用「在我的電腦跑了幾秒」比較兩個解法。

本章不會先要求讀者記住 `O(1)`、`O(n)`、`O(n²)` 或 `O(log n)`。內容會先從具體問題開始，觀察資料量增加時，程式需要多做多少工作，再逐步將這些現象轉換成複雜度符號。

本章涵蓋：

- 輸入規模 `n` 代表什麼。
- 為什麼需要 Big-O。
- `O(1)`、`O(n)`、`O(n²)` 與 `O(log n)` 的具體意義。
- 如何計算迴圈的總工作量。
- 為什麼兩層迴圈不一定都是 `O(n²)`。
- 空間複雜度與額外空間。
- 最好、最差、平均與攤銷成本。
- 如何從資料範圍初步判斷解法是否可行。

## 適用讀者

- 知道複雜度符號存在，但不清楚它們實際描述什麼的讀者。
- 看見 `O(n)` 或 `O(n²)` 時，只能把它當成需要記憶的結論的讀者。
- 能閱讀基本 `for` 迴圈，但不確定如何計算整段程式工作量的讀者。
- 容易只看迴圈層數，沒有觀察每個變數總共移動幾次的讀者。
- 想理解時間與記憶體取捨的讀者。

## 2.1 為什麼需要複雜度

假設有兩個找最大值的程式：

- 程式 A 在電腦甲執行，需要 0.2 秒。
- 程式 B 在電腦乙執行，需要 0.1 秒。

不能只根據秒數判斷程式 B 的演算法比較好，因為執行時間還受到很多因素影響：

- 電腦處理器速度。
- 編譯器與最佳化設定。
- 同時執行的其他程式。
- 輸入資料大小。
- 記憶體與 Cache 狀態。
- 程式語言與容器實作。

演算法分析需要一種比較不依賴特定電腦的方法。我們真正想問的是：

> 當輸入資料逐漸增加時，程式的工作量以什麼方式增加？

例如，找最大值時，每個數字通常都要看一次：

| 數字數量 | 大約需要查看的次數 |
|---:|---:|
| 10 | 10 |
| 100 | 100 |
| 1,000 | 1,000 |
| 100,000 | 100,000 |

資料量變成 10 倍，查看次數也大約變成 10 倍。這種工作量成長方式稱為線性成長，通常寫成 `O(n)`。

因此，`O(n)` 不是一段程式實際執行了幾秒，也不是神秘公式。它是在描述：

> 工作量會隨輸入規模成比例增加。

## 2.2 輸入規模 n 是什麼

複雜度中的 `n` 代表輸入規模。它不是固定代表某個數值，也不一定等於輸入資料本身的內容。

### Array 問題

對一個整數 Vector：

```cpp
std::vector<int> nums{7, 3, 9, 2};
```

`n` 通常代表元素數量：

```text
n = nums.size() = 4
```

### String 問題

對字串：

```text
"hello"
```

`n` 通常代表字串長度。在 `std::string` 中，它更精確地代表 Byte 數；Unicode 的可見字元數可能不同。

### Graph 問題

Graph 通常有兩個重要規模：

- `V`：Vertex 數量。
- `E`：Edge 數量。

因此 Graph Traversal 常寫成 `O(V + E)`，因為它可能需要處理每個 Vertex 和每條 Edge。

### 數值問題

如果輸入是一個整數 `x`，有時 `n` 代表 `x` 的數值，有時代表表示 `x` 所需的 Bit 數。分析前必須先定義輸入規模。

## 2.3 O(1)：固定工作量

`O(1)` 表示工作量不會因主要輸入規模增加而一起增加。

### 具體例子：讀取第一個元素

```cpp
int firstValue(const std::vector<int>& nums)
{
    return nums[0];
}
```

不論 Vector 有 10 個、1,000 個或 100,000 個元素，這段程式都只讀取 Index 0。

| 元素數量 | 讀取次數 |
|---:|---:|
| 10 | 1 |
| 1,000 | 1 |
| 100,000 | 1 |

因此它相對於 Vector 長度是 `O(1)`。

### O(1) 不代表只執行一行

下面的程式做了數次固定操作：

```cpp
int calculate(int a, int b)
{
    int sum = a + b;
    int difference = a - b;
    return sum * difference;
}
```

它不是只做一件事，但操作次數不會隨某個大型輸入容器增長，因此仍可視為 `O(1)`。

### O(1) 不代表實際時間一定相同

不同輸入可能造成小幅時間差，硬體也可能影響時間。`O(1)` 只表示工作量不隨主要輸入規模成長。

## 2.4 O(n)：資料增加多少，工作量也增加多少

### 問題：找出最大值

輸入：`[7, 3, 9, 2]`

人類會依序查看每個元素。程式也是如此：

```cpp
std::optional<int> maximum(const std::vector<int>& nums)
{
    if (nums.empty())
    {
        return std::nullopt;
    }

    int answer = nums[0];

    for (std::size_t i = 1; i < nums.size(); ++i)
    {
        answer = std::max(answer, nums[i]);
    }

    return answer;
}
```

### 程式做了多少次主要比較

如果有 `n` 個元素：

- 第一個元素用來初始化 `answer`。
- 剩下 `n - 1` 個元素各比較一次。

主要比較次數為：

```text
n - 1
```

Big-O 關心的是資料增加時的成長方式。`n - 1` 和 `n` 都是線性成長，因此寫成：

```text
O(n)
```

### 為什麼忽略減一

比較以下數量：

| n | n - 1 |
|---:|---:|
| 10 | 9 |
| 1,000 | 999 |
| 1,000,000 | 999,999 |

當 `n` 很大時，`-1` 不會改變成長類型。工作量仍和 `n` 成比例增加。

### O(2n) 為什麼仍寫成 O(n)

假設程式先完整走訪一次找最大值，再完整走訪一次找最小值，共處理約 `2n` 次。

資料變成 10 倍時，`2n` 仍變成 10 倍。常數 2 會影響實際時間，但不改變線性成長類型，因此 Big-O 寫成 `O(n)`。

## 2.5 O(n²)：檢查所有配對

### 問題：Two Sum 直接解法

如果要檢查所有不同 Index Pair，可以使用兩層迴圈：

```cpp
std::optional<std::pair<int, int>> twoSumBruteForce(
    const std::vector<int>& nums,
    int target)
{
    for (int i = 0; i < static_cast<int>(nums.size()); ++i)
    {
        for (int j = i + 1; j < static_cast<int>(nums.size()); ++j)
        {
            long long sum = static_cast<long long>(nums[i]) + nums[j];
            if (sum == target)
            {
                return std::pair{i, j};
            }
        }
    }

    return std::nullopt;
}
```

### Pair 數量如何增加

假設有 `n` 個元素：

- Index 0 可和後面 `n - 1` 個位置配對。
- Index 1 可和後面 `n - 2` 個位置配對。
- 之後依序減少。

總 Pair 數為：

```text
(n - 1) + (n - 2) + ... + 2 + 1
```

它等於：

```text
n × (n - 1) / 2
```

觀察實際數量：

| n | 不同 Pair 數量 |
|---:|---:|
| 10 | 45 |
| 100 | 4,950 |
| 1,000 | 499,500 |
| 10,000 | 49,995,000 |

當 `n` 變成大約 10 倍，Pair 數量會接近 100 倍。這是平方成長，因此寫成 `O(n²)`。

### 為什麼忽略除以 2

精確 Pair 數是 `(n² - n) / 2`。Big-O 關心最高成長項：

```text
n² 的成長速度高於 n
除以 2 是固定常數
```

因此最後寫成 `O(n²)`。

### 兩層迴圈不一定都是 O(n²)

不能只看到兩層迴圈就直接判定 `O(n²)`。需要觀察內層總共執行幾次。

例如 Sliding Window 中，`right` 和 `left` 都只會由左往右移動。即使語法有 `for` 和 `while`，兩個 Pointer 各自最多移動 `n` 次，總工作量可能仍是 `O(n)`。

## 2.6 O(log n)：每次排除一部分資料

### 具體問題：猜 1 到 100 的數字

假設答案位於 1 到 100，每次猜完都會知道答案比較大或比較小。

如果從 1 開始依序猜，最差可能猜 100 次。

更有效的方式是每次猜目前範圍中間：

| 步驟 | 目前範圍 | 猜測 | 得到的資訊 |
|---:|---|---:|---|
| 1 | 1 到 100 | 50 | 假設答案更大，排除 1 到 50 |
| 2 | 51 到 100 | 75 | 假設答案更小，排除 75 到 100 |
| 3 | 51 到 74 | 62 | 繼續排除一半附近的範圍 |

每次都把候選範圍縮小成大約一半：

```text
100 → 50 → 25 → 12 → 6 → 3 → 1
```

大約 7 次便能縮小到一個候選。

### log₂ n 在問什麼

`log₂ n` 可以理解成：

> `n` 連續除以 2，需要幾次才會接近 1？

| n | 大約可除以 2 的次數 |
|---:|---:|
| 8 | 3 |
| 16 | 4 |
| 1,024 | 10 |
| 1,048,576 | 20 |

即使資料從 1,024 增加到一百多萬，次數只從 10 增加到 20。這種成長比 `O(n)` 慢很多。

### O(log n) 的必要條件

不是所有問題都能每次排除一半。通常需要：

- 資料已排序。
- 或判斷條件具有單調性。
- 每次判斷後能確定某一段不可能包含答案。

如果無法安全排除一部分候選，就不能只因為想加速而使用 Binary Search。

## 2.7 如何分析連續與巢狀迴圈

### 連續迴圈的工作量相加

```cpp
for (int value : nums)
{
    processA(value);
}

for (int value : nums)
{
    processB(value);
}
```

第一個迴圈處理 `n` 次，第二個也處理 `n` 次：

```text
n + n = 2n
```

Big-O 寫成 `O(n)`。

### 真正的完整巢狀迴圈工作量相乘

```cpp
for (int i = 0; i < n; ++i)
{
    for (int j = 0; j < n; ++j)
    {
        process(i, j);
    }
}
```

外層每一次，內層都完整執行 `n` 次：

```text
n × n = n²
```

所以是 `O(n²)`。

### 看總移動量，不只看縮排

```cpp
int right = 0;

for (int left = 0; left < n; ++left)
{
    while (right < n && condition(left, right))
    {
        ++right;
    }
}
```

`right` 不會每次外層迴圈都回到 0。它在整段程式中最多從 0 走到 `n`，總共最多移動 `n` 次。

因此分析時要問：

- 每個變數是每輪重新開始，還是全程只向前？
- 每個元素總共會被處理幾次？
- 內層工作是否真的對每次外層都完整重做？

## 2.8 空間複雜度

時間複雜度描述工作量；空間複雜度描述演算法額外需要多少記憶體。

### O(1) 額外空間

找最大值只使用固定數量變數：

- `answer`
- `i`

不論輸入有多少元素，額外變數數量大致固定，因此額外空間是 `O(1)`。

### O(n) 額外空間

Two Sum 的 Hash Table 最差可能保存接近 `n` 筆資料：

```text
數字 → Index
```

輸入越大，Map 可能越大，所以額外空間是 `O(n)`。

### 輸入空間和額外空間

分析時通常會明確寫「額外空間」。輸入 Vector 本身已經存在，不是演算法額外建立的資料。

不過，如果函式用傳值方式接收 Vector：

```cpp
void solve(std::vector<int> nums)
```

會複製一份資料，這可能造成 `O(n)` 額外成本。

使用：

```cpp
void solve(const std::vector<int>& nums)
```

可以直接參考原資料，避免複製。

### 遞迴也會使用空間

每次函式呼叫都需要保存部分執行狀態。遞迴深度為 `n` 時，Call Stack 可能使用 `O(n)` 空間，即使程式中沒有建立 Vector 或 Map。

## 2.9 最好、最差、平均與攤銷

### 最好情況

Two Sum 直接解法如果第一組 Pair 就是答案，很快便會回傳。

### 最差情況

如果沒有答案，或答案在最後才被檢查，程式需要檢查所有 Pair。

演算法複雜度若未特別說明，解題時常討論最差情況，因為它提供一個上限。

### 平均情況

平均情況需要知道輸入分布。`std::unordered_map` 的查找通常描述為平均 `O(1)`，但不能將它誤寫成無條件的最差 `O(1)`。

### 攤銷成本

`std::vector::push_back` 通常很快，但容量不足時需要：

1. 申請更大的記憶體。
2. 搬移原本所有元素。
3. 加入新元素。

某一次擴容可能需要 `O(n)`，但不是每次都擴容。觀察大量 `push_back` 的平均成本，通常稱為攤銷 `O(1)`。

攤銷不是機率平均，而是把偶爾昂貴的工作分配到一連串操作中分析。

## 2.10 從輸入限制選擇解法

輸入規模可以幫助初步排除方法。以下只是粗略參考，不是固定保證：

| 輸入規模 | 常見可評估方向 |
|---:|---|
| `n <= 10` | Permutation、完整搜尋 |
| `n <= 20` | `O(2^n)`、Bitmask |
| `n <= 1,000` | 部分 `O(n²)` 解法 |
| `n <= 100,000` | 常見目標為 `O(n log n)` 或 `O(n)` |
| 更大 | 線性、對數、數學或特殊結構 |

還要一起考慮：

- 測試案例數量。
- 每輪工作的實際成本。
- 程式語言與容器。
- 記憶體限制。
- 是否需要輸出大量答案。

如果題目要求輸出所有 `2^n` 個 Subset，光是輸出本身就需要指數規模，不能期待整體時間是 `O(n)`。

## 2.11 常見問題與判讀

| 現象 | 可能原因 | 第一輪檢查 |
|---|---|---|
| 看到兩層迴圈就寫 `O(n²)` | 只看語法層數 | 每個 Pointer 總共移動幾次 |
| 函式只有一個迴圈卻很慢 | 迴圈內有複製、排序或容器操作 | 每行呼叫的成本 |
| Hash Table 被寫成最差 `O(1)` | 混淆平均與最差 | 容器提供的複雜度語意 |
| 遞迴記憶體超限 | 忽略 Call Stack | 最大遞迴深度 |
| 兩段 `O(n)` 被算成 `O(n²)` | 把連續工作誤認成巢狀工作 | 工作量是相加還是相乘 |
| 小資料最佳化後反而較慢 | 常數、配置與 Cache 成本 | 用實際測量補充 Big-O |
| 不知道 `n` 代表什麼 | 輸入規模未定義 | 元素數、Vertex、Edge 或 Bit 數 |

## 2.13 本章重點

1. 複雜度描述輸入增加時，工作量與額外空間如何成長。
2. `n` 必須先依問題定義，常見是元素數量。
3. `O(1)` 表示工作量不隨主要輸入規模增加。
4. `O(n)` 表示資料增加多少，工作量也大致增加多少。
5. `O(n²)` 常出現在所有 Pair 或二維候選空間。
6. `O(log n)` 常出現在每次能按比例縮小候選範圍的問題。
7. Big-O 會忽略固定常數與低次項，但實際效能仍受常數和硬體影響。
8. 兩層迴圈不一定是 `O(n²)`，要分析總工作量。
9. 空間複雜度需要包含額外容器、複製與遞迴 Stack。
10. 輸入限制是選擇可行演算法的重要依據。
