本章使用兩個主要案例：

- 從一組數字中找出最大值。

## 1.1 演算法的基本概念

演算法是一組用來解決特定問題的明確步驟。

假設現在有四個數字：`7、3、9、2`，問題是找出最大的數字。即使不寫程式，也可以依序處理：

1. 先看 `7`，暫時把它當成最大值。
2. 接著看 `3`。`3` 沒有比 `7` 大，最大值仍是 `7`。
3. 接著看 `9`。`9` 比 `7` 大，把最大值更新成 `9`。
4. 最後看 `2`。`2` 沒有比 `9` 大，最大值仍是 `9`。
5. 所有數字都處理完，答案是 `9`。

這組步驟已經是一個演算法。程式只是把這些步驟寫成電腦可以執行的形式。

### 演算法的五項基本特性

| 特性 | 意義 | 找最大值案例 |
|---|---|---|
| 輸入 | 演算法開始前取得的資料 | `7、3、9、2` |
| 輸出 | 問題要求產生的結果 | 最大值 `9` |
| 明確性 | 每個步驟都有清楚且唯一的意思 | 比較目前數字和目前最大值 |
| 有限性 | 經過有限步驟後會停止 | 每個元素處理一次後結束 |
| 可行性 | 每個步驟都能實際執行 | 整數比較與變數更新 |

#### 輸入

輸入是演算法開始前取得的資料。輸入可以是整數、字串、Array、Tree、Graph，或其他資料結構。

演算法也可能沒有外部輸入，但多數練習題會提供一組資料。

#### 輸出

輸出是題目要求的結果。輸出不一定只是單一數字，也可能是：

- 一個 Index。
- 一組 Index。
- 排序後的資料。
- 一條路徑。
- 修改後的原始容器。

因此，讀題時不能只看輸入，也要確認最後到底要回傳什麼。

#### 明確性

每個步驟都必須能被精確執行。

以下描述不夠明確：

> 如果數字很大，就處理一下。

較明確的描述是：

> 如果目前數字大於目前最大值，就把目前最大值更新成目前數字。

#### 有限性

演算法必須在有限步驟後停止。找最大值時，每個元素只看一次，所有元素處理完便結束。

如果迴圈條件或更新寫錯，程式可能永遠重複執行，形成無窮迴圈。

#### 可行性

每個步驟都必須真的能被執行。「比較兩個整數」是可行步驟；「直接猜出所有答案」則不是明確且可執行的步驟。

### 有限性與效率不同

有限性回答的是：

> 這個方法最後會不會停止？

效率回答的是：

> 這個方法需要多少工作和記憶體？

一個方法可能最後會停止，但資料很多時需要非常久。第 2 章會再從具體例子說明如何描述工作量。

## 1.2 如何描述一個問題

寫程式之前，先把問題拆成幾個可以回答的部分。

### 輸入是什麼

以找最大值為例，輸入是一組整數。還需要確認：

- 可能有幾個數字？
- 可能完全沒有數字嗎？
- 數字可能是負數嗎？
- 數字可能重複嗎？
- 資料是否已排序？

### 輸出是什麼

「找最大值」可能有不同要求：

- 回傳最大的數值。
- 回傳最大值所在的 Index。
- 回傳所有最大值所在的 Index。

如果只回傳數值，程式只需要記住目前最大值。如果還要回傳位置，就要另外記住最大值出現在哪個 Index。

### 邊界情況是什麼

假設輸入為空：

```text
[]
```

這組資料沒有最大值。因此函式不能直接使用第一個元素，也不能任意回傳 `0`，因為 `0` 可能是合法資料。

C++ 可以使用 `std::optional<int>` 表示兩種情況：

- 有一個 `int` 答案。
- 沒有答案。

這是函式介面的設計。找最大值的核心演算法仍然是「逐一比較並保存目前最大值」。

## 1.3 完整案例：找最大值

### 問題與具體輸入

輸入：`[7, 3, 9, 2]`

要求：找出最大的數字。

預期輸出：`9`

### 人類手動解法

| 步驟 | 新看到的數字 | 更新前最大值 | 判斷 | 更新後最大值 |
|---:|---:|---:|---|---:|
| 初始化 | 7 | 尚未設定 | 先使用第一個數字 | 7 |
| 1 | 3 | 7 | `3 < 7`，不更新 | 7 |
| 2 | 9 | 7 | `9 > 7`，更新 | 9 |
| 3 | 2 | 9 | `2 < 9`，不更新 | 9 |

整個過程只需要長期記住一項資訊：

> 目前已經看過的數字中，最大的數字是多少？

程式使用變數 `answer` 保存這項資訊。

### 變數身分表

| 名稱 | 它保存的資訊 | 何時改變 |
|---|---|---|
| `nums` | 完整輸入資料 | 函式中不修改 |
| `i` | 這一輪正在處理的 Index | 每輪加一 |
| `nums[i]` | 這一輪看到的數字 | 隨 `i` 改變 |
| `answer` | 目前已處理範圍內的最大值 | 遇到更大值時更新 |

`answer` 在迴圈執行期間不一定是最終答案。它代表的是「目前最大值」。等全部元素處理完，它才成為整組資料的最大值。

### C++ 實作

```cpp
#include <algorithm>
#include <optional>
#include <vector>

std::optional<int> maximum(const std::vector<int>& nums)
{
    // 空的 Vector 沒有最大值，所以回報「沒有答案」。
    if (nums.empty())
    {
        return std::nullopt;
    }

    // 現在只看過第一個元素。
    // 因此第一個元素就是目前已看過元素中的最大值。
    int answer = nums[0];

    // Index 0 已經用來初始化 answer，所以從 Index 1 開始。
    for (std::size_t i = 1; i < nums.size(); ++i)
    {
        // 比較目前最大值和本輪的新數字，保存較大者。
        answer = std::max(answer, nums[i]);
    }

    // 所有元素都處理完，answer 現在是整個 Vector 的最大值。
    return answer;
}
```

### 程式區塊解讀

#### 為什麼先檢查 `nums.empty()`

後面會讀取 `nums[0]`。如果 Vector 是空的，Index 0 不存在，直接讀取會形成錯誤。因此程式先處理空輸入。

#### 為什麼使用第一個元素初始化

```cpp
int answer = nums[0];
```

目前只看過第一個元素，所以它自然是目前最大值。

不能固定寫成：

```cpp
int answer = 0;
```

因為輸入可能全是負數，例如 `[-7, -3, -9]`。如果從 `0` 開始，程式會回傳輸入中根本不存在的 `0`。

#### 為什麼從 Index 1 開始

Index 0 已經用來設定 `answer`，不必再比較一次。因此迴圈從 Index 1 開始，依序處理剩餘元素。

#### `std::max` 做了什麼

```cpp
answer = std::max(answer, nums[i]);
```

這一行可以讀成：

> 比較目前最大值和本輪看到的數字，將較大的數字保存回 `answer`。

例如 `answer = 7`、`nums[i] = 9` 時，`std::max(7, 9)` 得到 `9`，所以 `answer` 更新成 `9`。

### 執行追蹤

| i | `nums[i]` | 進入本輪前 `answer` | 執行的比較 | 本輪後 `answer` |
|---:|---:|---:|---|---:|
| 1 | 3 | 7 | `max(7, 3)` | 7 |
| 2 | 9 | 7 | `max(7, 9)` | 9 |
| 3 | 2 | 9 | `max(9, 2)` | 9 |

迴圈結束後，`answer` 為 `9`。

### 為什麼這個方法正確

每一輪結束後，都有一件事情成立：

> `answer` 是目前已經看過的元素中的最大值。

初始化時只看過第一個元素，因此成立。

每一輪都比較舊的 `answer` 和新元素，並保存較大值，所以這件事情會繼續成立。

所有元素都處理完後，「目前已看過的元素」就是整個 Vector，因此 `answer` 是整組資料的最大值。

這種在每一輪都保持成立的敘述，稱為 Loop Invariant。現在先把它理解成「程式每一輪都要維持的規則」即可。

### 本例使用的 C++ 語法

#### `std::vector<int>`

代表一組依序存放的整數。C++ 的 Index 從 0 開始。

```text
Index:  0  1  2  3
Value:  7  3  9  2
```

#### `const std::vector<int>& nums`

拆開理解：

- `std::vector<int>`：一組整數。
- `nums`：這組輸入在函式中的名稱。
- `&`：函式直接參考原資料，不另外複製整份 Vector。
- `const`：函式不會修改 `nums`。

#### `std::optional<int>`

表示函式可能回傳一個 `int`，也可能沒有答案。

#### `std::size_t`

是 C++ 常用來表示容器大小與 Index 的非負整數型別。這裡的 `i` 只會從 1 往上走，不需要表示負數。

## 1.4 演算法和程式的差異

找最大值的演算法可以用自然語言表示：

```text
如果沒有元素，回報沒有答案。
先把第一個元素當成目前最大值。
依序檢查剩餘元素。
如果新元素比較大，就更新目前最大值。
所有元素看完後，回傳目前最大值。
```

C++ 程式則進一步決定：

- 使用 `std::vector<int>` 保存輸入。
- 使用 `std::optional<int>` 表示可能沒有答案。
- 使用變數 `answer` 保存目前最大值。
- 使用 `for` 迴圈逐一處理元素。
- 使用 `std::max` 完成比較。

演算法描述「如何解決問題」。程式描述「如何用特定語言表達這些步驟」。

## 1.5 為什麼先寫直接解法

直接解法依照題目定義，完整檢查所有可能答案。它不一定最快，但通常最容易理解與驗證。

直接解法的用途包括：

- 確認自己沒有誤解題目。
- 明確知道候選答案有哪些。
- 建立一個容易相信的基準版本。
- 找出程式在哪裡重複工作。
- 測試後續速度較快的版本。

最佳化通常不是突然想到一個公式，而是先找出直接解法重複做了什麼，再選擇適合的資料結構減少這些工作。

## 1.6 完整案例：Two Sum

### 問題規格

輸入：

- 整數 Vector `nums`。
- 目標值 `target`。

要求：找出兩個不同 Index，使兩個位置的數字相加等於 `target`。

範例：

```text
nums = [2, 7, 11, 15]
target = 9
```

因為 `nums[0] + nums[1] = 2 + 7 = 9`，所以可回傳 Index 0 和 1。

### 人類最直接的做法

逐一檢查所有不同位置的配對：

| 第一個位置 | 第二個位置 | 計算 | 是否等於 9 |
|---:|---:|---|---|
| 0 | 1 | `2 + 7 = 9` | 是 |
| 0 | 2 | `2 + 11 = 13` | 否 |
| 0 | 3 | `2 + 15 = 17` | 否 |
| 1 | 2 | `7 + 11 = 18` | 否 |
| 1 | 3 | `7 + 15 = 22` | 否 |
| 2 | 3 | `11 + 15 = 26` | 否 |

如果題目只要求任意一組答案，找到第一組後即可停止。

### 直接解法的變數身分表

| 變數 | 保存的資訊 |
|---|---|
| `i` | 第一個被選中的 Index |
| `j` | 第二個被選中的 Index |
| `nums[i]` | 第一個數字 |
| `nums[j]` | 第二個數字 |
| `sum` | 兩個數字相加的結果 |
| `target` | 希望得到的目標總和 |

### C++ 直接解法

```cpp
#include <optional>
#include <utility>
#include <vector>

std::optional<std::pair<int, int>> twoSumBruteForce(
    const std::vector<int>& nums,
    int target)
{
    // i 代表第一個被選中的位置。
    for (int i = 0; i < static_cast<int>(nums.size()); ++i)
    {
        // j 從 i + 1 開始，確保兩個位置不同，
        // 也避免重複檢查 (0, 1) 和 (1, 0)。
        for (int j = i + 1; j < static_cast<int>(nums.size()); ++j)
        {
            // 先轉成 long long 再相加，降低 int 加法溢位風險。
            long long sum = static_cast<long long>(nums[i]) + nums[j];

            if (sum == target)
            {
                return std::pair{i, j};
            }
        }
    }

    return std::nullopt;
}
```

### 為什麼 `j` 從 `i + 1` 開始

這樣可以同時避免：

- 使用同一個位置兩次，例如 `(0, 0)`。
- 把同一組位置檢查兩次，例如 `(0, 1)` 和 `(1, 0)`。

每一組不同 Index 的 Pair 只會被檢查一次。

### 找出重複工作

假設目前數字是 `7`，Target 是 `9`。另一個數字必須是：

```text
9 - 7 = 2
```

問題可以改寫成：

> 數字 2 以前有沒有出現過？

直接解法會不斷重新掃描資料尋找補數。Hash Table 可以把以前看過的數字和位置記錄起來，讓後面的元素快速查詢。

### Hash Table 要保存什麼

| Map 欄位 | 保存內容 |
|---|---|
| Key | 以前看過的數字 |
| Value | 該數字出現過的 Index |

例如 `2 → 0` 代表數字 2 曾經出現在 Index 0。

### Hash Table 解法

```cpp
#include <optional>
#include <unordered_map>
#include <utility>
#include <vector>

std::optional<std::pair<int, int>> twoSumHash(
    const std::vector<int>& nums,
    int target)
{
    // Key 是以前看過的數字。
    // Value 是該數字出現過的 Index。
    std::unordered_map<long long, int> indexByValue;

    for (int i = 0; i < static_cast<int>(nums.size()); ++i)
    {
        // 本輪正在處理的數字。
        long long currentValue = nums[i];

        // 如果目前選擇 currentValue，
        // 另一個數字必須是 target - currentValue。
        long long neededValue =
            static_cast<long long>(target) - currentValue;

        // 查詢 neededValue 以前是否出現過。
        auto found = indexByValue.find(neededValue);

        if (found != indexByValue.end())
        {
            // found->second 是 neededValue 以前出現的 Index。
            int previousIndex = found->second;
            return std::pair{previousIndex, i};
        }

        // 本輪找不到答案，所以保存目前數字和位置，
        // 讓後面的元素可以查詢它。
        indexByValue[currentValue] = i;
    }

    return std::nullopt;
}
```

### Hash 解法的變數身分表

| 變數 | 保存的資訊 | 例子 |
|---|---|---|
| `i` | 本輪處理的 Index | `1` |
| `currentValue` | 本輪數字 | `7` |
| `neededValue` | 為達成 Target 還缺的數字 | `2` |
| `indexByValue` | 以前看過的數字與位置 | `{2 → 0}` |
| `found` | 查詢結果所在的位置 | 指向 `2 → 0` |
| `previousIndex` | 補數先前出現的 Index | `0` |

### 為什麼先查再插

假設輸入只有 `[3]`，Target 是 `6`。不能用 Index 0 兩次。

先查再插時，查詢補數 `3` 的那一刻，Map 還是空的，因此不會錯誤地把目前元素和自己配對。

### Hash 解法執行追蹤

輸入：`nums = [2, 7, 11, 15]`，`target = 9`

| i | 本輪數字 | 還缺的數字 | 查詢前 Map | 查詢結果 | 本輪動作 |
|---:|---:|---:|---|---|---|
| 0 | 2 | 7 | 空 | 找不到 | 保存 `2 → 0` |
| 1 | 7 | 2 | `{2 → 0}` | 找到 Index 0 | 回傳 `{0, 1}` |

### 本例使用的 C++ 語法

#### `std::pair<int, int>`

用來一起保存兩個 `int`。這裡保存兩個答案 Index。

#### `std::unordered_map<long long, int>`

保存 Key 和 Value 的對應關係。這裡的 Key 是數字，Value 是 Index。

#### `find`

```cpp
auto found = indexByValue.find(neededValue);
```

用來查詢 Key 是否存在。

如果找不到，結果會等於：

```cpp
indexByValue.end()
```

因此 `found != indexByValue.end()` 表示成功找到。

#### `found->second`

Map 中的一筆資料包含 Key 和 Value：

- `first` 是 Key。
- `second` 是 Value。

所以 `found->second` 得到以前保存的 Index。

#### `static_cast<long long>`

先把數值轉成 `long long`，再進行加減，降低两个较大 `int` 在中間運算時溢位的風險。

### 為什麼 Hash 解法正確

每一輪開始時，Map 保存目前 Index 之前看過的數字和位置。

如果答案是 `(j, i)`，而且 `j < i`，那麼走到 `i` 時，`nums[j]` 已經被存入 Map。程式計算 `target - nums[i]` 後，就能查到 `nums[j]`。

這也解釋了為什麼 Map 只保存「以前看過」的資料，以及為什麼必須先查再插。

## 1.7 如何閱讀陌生程式

遇到陌生程式時，不要立刻從第一行逐字猜。可以依序回答：

1. 函式收到什麼輸入？
2. 函式最後要回傳什麼？
3. 每個主要變數保存哪一項現實資訊？
4. 迴圈每一輪處理哪一部分資料？
5. `if` 條件在判斷什麼？
6. 哪些變數會在本輪更新？
7. 哪些情況會提前 `return`？
8. 使用 3 到 4 個元素，手動執行每一輪。

如果一個變數的用途不清楚，先建立變數身分表，而不是只看它的名稱。

## 1.8 常見問題與判讀

| 現象 | 可能原因 | 第一輪檢查 |
|---|---|---|
| 看見完整函式就失去方向 | 尚未辨識輸入與輸出 | 先只看函式名稱、參數和回傳型別 |
| 不知道變數用途 | 只看名稱，沒有連接現實資訊 | 建立變數身分表 |
| 迴圈看不懂 | 沒有逐輪追蹤 | 使用小型輸入手動執行 |
| 最大值在全負數時錯誤 | `answer` 初始化成 0 | 使用第一個元素初始化 |
| Two Sum 使用同一 Index | 先插入目前值再查詢 | 改成先查再插 |
| Two Sum 大數錯誤 | `int` 中間運算溢位 | 加減前提升到 `long long` |
| 註解很多仍看不懂 | 註解只翻譯語法 | 改成說明變數語意與設計理由 |

## 1.10 本章重點

1. 演算法是解決問題的明確步驟，程式是它的 C++ 表達。
2. 閱讀程式前，先理解人類會如何手動處理問題。
3. 每個變數都應對應一項需要被記住的資訊。
4. 找最大值只需要記住目前最大值。
5. 直接解法有助於確認候選、找出瓶頸並建立測試基準。
6. Two Sum 的 Hash Table 保存以前看過的數字與位置。
7. 有用的註解應說明設計理由，而不只是將語法翻成中文。
8. 面對抽象程式時，使用具體資料逐輪追蹤，是重要的理解方法。
