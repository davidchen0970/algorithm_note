# 第 1 章　演算法是什麼

## 適用範圍

本章從最基礎的角度說明「演算法」到底是什麼，以及人類平常解決問題的方式，如何逐步轉換成電腦可以執行的 C++ 程式。

本章不假設讀者已經熟悉演算法，也不假設讀者能直接看懂 C++ 範例。每段程式都會先從具體問題開始，再依序說明：

1. 人類會怎麼處理這個問題。
2. 解題過程中需要記住哪些資訊。
3. 這些資訊如何變成程式裡的變數。
4. 每段程式碼的用途。
5. 程式執行時，變數如何逐步改變。
6. 為什麼最後能得到正確答案。

本章使用兩個主要問題：

- 從一組數字中找出最大值。
- 從一組數字中找出相加等於目標值的兩個位置。

## 1.1 演算法的定義

演算法是一組用來解決特定問題的步驟。

例如，現在有四個數字：

```text
7, 3, 9, 2
```

問題是：

```text
哪一個數字最大？
```

你可能會這樣處理：

```text
先看 7，把 7 暫時當成最大值。

再看 3。
3 沒有比 7 大，所以最大值仍是 7。

再看 9。
9 比 7 大，所以把最大值改成 9。

最後看 2。
2 沒有比 9 大，所以最大值仍是 9。

所有數字都看完後，得到答案 9。
```

這一連串明確的處理步驟，就是一個演算法。

### 1.1.1 演算法的五項基本特性

一個完整的演算法通常具有以下五項特性。

#### 輸入

輸入是演算法開始前取得的資料。

在找最大值的問題中，輸入是：

```text
[7, 3, 9, 2]
```

演算法也可以沒有外部輸入，但多數解題情境都會提供一組資料。

#### 輸出

輸出是問題要求的結果。

在找最大值的問題中，輸出是：

```text
9
```

輸出不一定是單一數字，也可能是一組位置、一條路徑、排序後的資料，或修改後的原始容器。

#### 明確性

每個步驟必須有清楚的意思。

這句話不夠明確：

```text
如果數字很大，就處理一下。
```

這句話比較明確：

```text
如果目前數字大於目前最大值，就用目前數字取代目前最大值。
```

電腦只能執行已明確定義的比較與更新。

#### 有限性

演算法必須在有限步驟後結束。

找最大值時，每個元素只需要看一次。當所有元素都看完，演算法便會停止。

如果迴圈的控制條件寫錯，程式可能永遠重複執行。這種情況稱為無窮迴圈。

#### 可行性

每個步驟必須真的能被執行。

「比較兩個整數」是可執行的步驟。

「立刻猜出所有可能答案」不是一個明確且可執行的步驟。

### 1.1.2 有限性和效率不是同一件事

一個方法可能最後會結束，但花費非常久。

例如，檢查一百個數字的所有配對仍會結束，但資料量增加到十萬時，所需工作可能太多。

因此後續還要分析：

- 演算法是否會結束。
- 演算法需要多少工作。
- 演算法需要多少額外記憶體。

## 1.2 先把問題說清楚

寫程式前，先把問題拆成幾個可以回答的部分。

### 1.2.1 輸入是什麼

以找最大值為例：

```text
輸入是一組整數。
```

還要確認：

- 可能有幾個數字？
- 可能完全沒有數字嗎？
- 數字可能是負數嗎？
- 數字可能重複嗎？
- 數字是否已排序？

### 1.2.2 輸出是什麼

找最大值可能有不同輸出要求：

```text
回傳最大的數值
```

或：

```text
回傳最大值所在的位置
```

這兩個問題需要記住的資訊不同。

只回傳最大值時，可以只記住目前最大的數字。

如果要回傳位置，還需要記住最大值出現在哪個 Index。

### 1.2.3 空輸入怎麼辦

如果輸入是：

```text
[]
```

裡面沒有任何數字，因此不存在最大值。

不能隨意回傳 `0`，因為 `0` 可能正好是合法最大值。

C++ 可以使用 `std::optional<int>` 表達：

```text
可能有一個 int 答案
也可能沒有答案
```

這是一項介面設計，不是找最大值演算法本身的核心步驟。

## 1.3 第一個完整案例：找最大值

### 1.3.1 問題

輸入：

```text
[7, 3, 9, 2]
```

要求：

```text
找出最大的數字。
```

答案：

```text
9
```

### 1.3.2 人類會怎麼處理

第一步先看第一個數字：

```text
目前最大值 = 7
```

再看下一個數字 `3`：

```text
3 比 7 小
目前最大值仍是 7
```

再看 `9`：

```text
9 比 7 大
目前最大值改成 9
```

再看 `2`：

```text
2 比 9 小
目前最大值仍是 9
```

所有數字都處理完後，目前最大值就是答案。

### 1.3.3 解題過程需要記住什麼

整個過程只需要長期記住一項資訊：

```text
目前已看過的數字中，最大的數字是多少？
```

程式使用變數 `answer` 保存這項資訊：

```cpp
int answer;
```

`answer` 在迴圈執行期間不是「已經確定的最終答案」。

它代表：

```text
目前處理範圍內的最大值
```

隨著更多元素被處理，`answer` 可能被更新。

## 1.4 看懂第一段 C++

完整程式如下：

```cpp
#include <algorithm>
#include <optional>
#include <vector>

std::optional<int> maximum(const std::vector<int>& nums)
{
    // 空的 Vector 沒有最大值，因此回報「沒有答案」。
    if (nums.empty())
    {
        return std::nullopt;
    }

    // 目前只看過第一個元素。
    // 所以第一個元素就是目前看過的元素中的最大值。
    int answer = nums[0];

    // Index 0 已經用來初始化 answer，所以從 Index 1 開始檢查。
    for (std::size_t i = 1; i < nums.size(); ++i)
    {
        // 比較「目前最大值」和「這一輪看到的數字」。
        // 將兩者中較大的數字保存回 answer。
        answer = std::max(answer, nums[i]);
    }

    // 所有元素都處理完後，answer 就是整個 Vector 的最大值。
    return answer;
}
```

### 1.4.1 `std::vector<int>` 是什麼

```cpp
std::vector<int>
```

代表一組可以依序存放的整數。

例如：

```cpp
std::vector<int> nums{7, 3, 9, 2};
```

它的 Index 如下：

```text
Index:  0  1  2  3
Value:  7  3  9  2
```

因此：

```cpp
nums[0]
```

得到第一個值 `7`。

```cpp
nums[2]
```

得到第三個值 `9`。

C++ 的 Index 從 `0` 開始。

### 1.4.2 `const std::vector<int>& nums` 是什麼

把它拆開來看：

```text
std::vector<int>
一組整數

nums
這組輸入資料在函式裡的名稱

&
函式直接參考原本的 Vector，不另外複製整份資料

const
函式承諾不修改 nums
```

因此：

```cpp
const std::vector<int>& nums
```

可以讀成：

```text
這個函式收到一組不會被它修改的整數 Vector，並直接參考原資料。
```

### 1.4.3 `std::optional<int>` 是什麼

```cpp
std::optional<int>
```

表示函式的結果有兩種可能：

```text
有一個 int 答案
```

或：

```text
沒有答案
```

輸入為空時：

```cpp
return std::nullopt;
```

代表沒有最大值。

### 1.4.4 `nums.empty()` 是什麼

```cpp
nums.empty()
```

用來詢問 Vector 是否沒有任何元素。

如果輸入是：

```text
[]
```

`nums.empty()` 會得到 `true`。

### 1.4.5 為什麼用 `nums[0]` 初始化

```cpp
int answer = nums[0];
```

目前只看過第一個元素，所以它自然是目前最大值。

不能把 `answer` 固定初始化成 `0`，因為輸入可能全是負數：

```text
[-7, -3, -9]
```

如果從 `0` 開始，程式會錯誤地回傳輸入中根本不存在的 `0`。

### 1.4.6 為什麼迴圈從 1 開始

Index `0` 已經被用來初始化 `answer`。

因此剩下需要檢查的是：

```text
Index 1 到最後一個 Index
```

所以寫成：

```cpp
for (std::size_t i = 1; i < nums.size(); ++i)
```

這個 `for` 可以拆成三部分：

```cpp
std::size_t i = 1
```

代表一開始先看 Index 1。

```cpp
i < nums.size()
```

代表只要 `i` 仍在 Vector 有效範圍內，就繼續執行。

```cpp
++i
```

代表每一輪結束後把 `i` 加一，前往下一個位置。

### 1.4.7 `std::max` 在做什麼

```cpp
std::max(answer, nums[i])
```

會比較兩個數字，回傳較大的那一個。

例如：

```cpp
std::max(7, 9)
```

得到：

```text
9
```

因此：

```cpp
answer = std::max(answer, nums[i]);
```

代表：

```text
比較目前最大值和新看到的數字，
把較大的值保存成新的目前最大值。
```

## 1.5 程式執行追蹤

輸入：

```text
nums = [7, 3, 9, 2]
```

初始化：

```text
answer = nums[0] = 7
```

| 迴圈輪次 | i | nums[i] | 進入本輪前 answer | 比較結果 | 本輪後 answer |
|---:|---:|---:|---:|---|---:|
| 1 | 1 | 3 | 7 | `max(7, 3)` | 7 |
| 2 | 2 | 9 | 7 | `max(7, 9)` | 9 |
| 3 | 3 | 2 | 9 | `max(9, 2)` | 9 |

迴圈結束後：

```text
answer = 9
```

### 1.5.1 為什麼這個方法正確

每一輪結束後，都有一件事情成立：

```text
answer 是目前已經看過的元素中的最大值。
```

開始時只看過 `nums[0]`，所以成立。

每次看到新元素時，程式比較 `answer` 和新元素，保存較大值，所以這件事情在下一輪仍然成立。

所有元素都處理完後，「目前看過的元素」就是整個 Vector，因此 `answer` 是整個 Vector 的最大值。

這種在每輪都保持成立的敘述，稱為 Loop Invariant。

## 1.6 演算法與程式的差異

找最大值的演算法可以用自然語言表示：

```text
如果沒有元素，回報沒有答案。
先把第一個元素當成目前最大值。
依序檢查剩餘元素。
如果新元素比較大，就更新目前最大值。
所有元素看完後，回傳目前最大值。
```

C++ 程式則決定：

- 使用 `std::vector<int>` 保存輸入。
- 使用 `std::optional<int>` 表示可能沒有答案。
- 使用 `answer` 保存目前最大值。
- 使用 `for` 逐一走訪元素。
- 使用 `std::max` 完成比較。

演算法描述「怎麼解問題」。

程式描述「如何用特定語言把這些步驟寫出來」。

## 1.7 直接解法的用途

直接解法是依照題目定義，完整檢查所有可能答案的方法。

它不一定最快，但通常最容易理解和驗證。

直接解法的用途包括：

- 確認自己沒有誤解題目。
- 確認候選答案有哪些。
- 建立一個較容易相信的基準版本。
- 找出程式重複做了哪些工作。
- 用來測試後續較快的版本。

後續的最佳化通常不是突然想到新公式，而是觀察直接解法在哪裡做了大量重複工作。

## 1.8 第二個完整案例：Two Sum

### 1.8.1 問題

輸入：

```text
nums = [2, 7, 11, 15]
target = 9
```

要求找出兩個不同位置，使這兩個位置的數字相加等於 `9`。

```text
nums[0] + nums[1]
= 2 + 7
= 9
```

所以答案是：

```text
Index 0 和 Index 1
```

### 1.8.2 人類最直接的做法

逐一檢查所有配對：

```text
2 + 7  = 9   找到答案
2 + 11 = 13
2 + 15 = 17
7 + 11 = 18
7 + 15 = 22
11 + 15 = 26
```

找到第一組符合條件的 Pair 後，就可以停止。

### 1.8.3 C++ 直接解法

```cpp
#include <optional>
#include <utility>
#include <vector>

std::optional<std::pair<int, int>> twoSumBruteForce(
    const std::vector<int>& nums,
    int target)
{
    // i 代表第一個被選中的位置。
    for (int i = 0; i < static_cast<int>(nums.size()); ++i)
    {
        // j 從 i + 1 開始，確保兩個位置不同，
        // 也避免重複檢查 (0, 1) 和 (1, 0)。
        for (int j = i + 1; j < static_cast<int>(nums.size()); ++j)
        {
            // 先轉成 long long 再相加，降低 int 加法溢位風險。
            long long sum = static_cast<long long>(nums[i]) + nums[j];

            if (sum == target)
            {
                return std::pair{i, j};
            }
        }
    }

    return std::nullopt;
}
```

### 1.8.4 變數代表什麼

```text
i
第一個被選中的 Index

j
第二個被選中的 Index

nums[i]
第一個數字

nums[j]
第二個數字

sum
這兩個數字相加的結果

target
我們希望得到的目標總和
```

### 1.8.5 為什麼 `j = i + 1`

如果 `j` 也從 `0` 開始，程式會發生兩個問題：

```text
可能檢查同一個位置兩次，例如 (0, 0)
可能重複檢查同一組配對，例如 (0, 1) 和 (1, 0)
```

從 `i + 1` 開始，可以確保每一組不同 Index 的 Pair 只檢查一次。

## 1.9 Two Sum 的 Hash Table 解法

### 1.9.1 直接解法重複做了什麼

假設目前看到數字 `7`，目標是 `9`。

另一個數字必須是：

```text
9 - 7 = 2
```

真正的問題可以改寫成：

```text
數字 2 以前有沒有出現過？
```

直接解法會一再掃描 Array 尋找補數。

Hash Table 可以保存以前看過的數字和位置，讓程式快速查詢。

### 1.9.2 Map 保存什麼

```text
Key
以前看過的數字

Value
該數字出現的 Index
```

例如：

```text
2 → 0
7 → 1
```

代表：

```text
數字 2 出現在 Index 0
數字 7 出現在 Index 1
```

### 1.9.3 完整 C++

```cpp
#include <optional>
#include <unordered_map>
#include <utility>
#include <vector>

std::optional<std::pair<int, int>> twoSumHash(
    const std::vector<int>& nums,
    int target)
{
    // Key 是以前看過的數字。
    // Value 是該數字出現過的 Index。
    std::unordered_map<long long, int> indexByValue;

    for (int i = 0; i < static_cast<int>(nums.size()); ++i)
    {
        // 本輪正在處理的數字。
        long long currentValue = nums[i];

        // 如果目前選擇 currentValue，
        // 另一個數字必須是 target - currentValue。
        long long neededValue =
            static_cast<long long>(target) - currentValue;

        // 查詢 neededValue 以前是否出現過。
        auto found = indexByValue.find(neededValue);

        if (found != indexByValue.end())
        {
            // found->second 是 neededValue 以前出現的 Index。
            int previousIndex = found->second;
            return std::pair{previousIndex, i};
        }

        // 這一輪找不到答案，所以把目前數字和位置保存起來，
        // 讓後面的元素可以查詢它。
        indexByValue[currentValue] = i;
    }

    return std::nullopt;
}
```

### 1.9.4 為什麼先查再插

假設只有一個數字：

```text
nums = [3]
target = 6
```

不能使用 Index 0 兩次。

先查再插時，查詢 `3` 的那一刻，Map 還是空的，因此不會錯誤地把目前元素和自己配對。

### 1.9.5 逐輪追蹤

輸入：

```text
nums = [2, 7, 11, 15]
target = 9
```

第一輪：

```text
i = 0
currentValue = 2
neededValue = 9 - 2 = 7
Map = 空
找不到 7
保存 2 → 0
```

第二輪：

```text
i = 1
currentValue = 7
neededValue = 9 - 7 = 2
Map = {2 → 0}
找到 2
previousIndex = 0
回傳 {0, 1}
```

### 1.9.6 `auto found` 是什麼

```cpp
auto found = indexByValue.find(neededValue);
```

`find` 會回傳一個 Iterator。

Iterator 可以理解為指向容器中某個項目的位置。

如果找不到，`find` 會回傳：

```cpp
indexByValue.end()
```

因此：

```cpp
found != indexByValue.end()
```

代表成功找到。

```cpp
found->second
```

取得這筆 Key-Value 資料中的 Value，也就是先前 Index。

## 1.10 如何閱讀陌生程式

看到一段陌生程式時，先不要從第一行開始逐字猜。

建議依序回答：

1. 函式收到什麼輸入？
2. 函式最後要回傳什麼？
3. 每個主要變數保存什麼資訊？
4. 迴圈每一輪處理哪一部分資料？
5. `if` 條件在判斷什麼？
6. 什麼情況下變數會更新？
7. 什麼情況下函式會提前 `return`？
8. 使用一組很小的實際資料，逐輪寫出變數值。

可以建立變數身分表：

| 變數 | 保存的資訊 | 何時更新 |
|---|---|---|
| `i` | 本輪處理的 Index | 每輪加一 |
| `answer` | 目前最大值 | 遇到更大值時 |
| `currentValue` | 本輪數字 | 每輪從 `nums[i]` 取得 |
| `neededValue` | 為達成 Target 還缺的數字 | 每輪重新計算 |
| `indexByValue` | 以前看過的數字與位置 | 本輪查詢失敗後 |

## 1.11 常見問題與判讀

| 現象 | 可能原因 | 第一輪檢查 |
|---|---|---|
| 看見完整函式就失去方向 | 尚未辨識輸入與輸出 | 先只看函式名稱、參數、回傳型別 |
| 不知道變數用途 | 只看變數名稱 | 寫出它保存的現實資訊 |
| 迴圈看不懂 | 沒有逐輪追蹤 | 使用 3 到 4 個元素手動執行 |
| 最大值在全負數時錯誤 | `answer` 初始化成 0 | 使用第一個元素初始化 |
| Two Sum 使用同一 Index | 先插入再查詢 | 改成先查再插 |
| Two Sum 大數錯誤 | `int` 加法溢位 | 加法前轉成 `long long` |
| 註解很多仍看不懂 | 註解只翻譯語法 | 改寫成設計理由和變數語意 |

## 1.13 本章重點

1. 演算法是解決問題的明確步驟，程式是它的具體 C++ 表達。
2. 閱讀程式前，先理解人類會怎麼手動處理問題。
3. 每個變數都應對應一項需要被記住的資訊。
4. 找最大值只需要記住目前最大值。
5. 直接解法有助於確認候選、找出瓶頸並建立測試基準。
6. Two Sum 的 Hash Table 保存以前看過的數字與位置。
7. 有用的註解應說明設計理由，而不只是把語法翻成中文。
8. 面對抽象程式時，使用具體資料逐輪追蹤是重要的理解方法。
