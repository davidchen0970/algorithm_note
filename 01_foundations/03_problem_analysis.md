# 第 3 章　解題前的問題分析

## 適用範圍

本章說明拿到一個題目後，在寫程式之前應該先完成哪些分析。

很多解題困難並不是不會寫 `for` 或 `if`，而是還沒有把題目整理成清楚的資料、條件與目標。若問題尚未整理完成，直接開始寫程式，常會出現以下情況：

- 寫到一半才發現漏看條件。
- 選擇了不適用的演算法。
- 不知道需要哪些變數。
- Sample 可以執行，但邊界資料失敗。
- 寫出一段程式，卻無法說明它正在解決哪個子問題。

本章會建立一套固定流程：

1. 移除題目的故事背景。
2. 找出真正的輸入與輸出。
3. 記錄資料大小、值域與特殊條件。
4. 確認答案來自哪些可能候選。
5. 使用小型資料手動解一次。
6. 先建立容易理解的直接解法。
7. 找出直接解法中的重複工作。
8. 再決定是否需要其他資料結構或演算法。

## 適用讀者

- 讀完題目後，經常不知道第一步要做什麼的讀者。
- 容易看到關鍵字便直接套用演算法模板的讀者。
- 能看懂別人的答案，但很難自己從空白開始的讀者。
- 常因漏看排序、重複值、負數、空輸入或輸出格式而失敗的讀者。
- 同時使用 C++ 與 C，需要先理解演算法核心，再處理語言差異的讀者。

## 3.1 解題前到底要分析什麼

假設題目如下：

> 給定一組整數，判斷是否有任何數字出現超過一次。

很多人看到後會立刻開始想：

```text
我要寫什麼迴圈？
我要用 Hash Table 嗎？
函式怎麼宣告？
```

但這些都不是第一個問題。

第一步應該先把題目整理成幾個明確欄位：

| 分析項目 | 本題內容 |
|---|---|
| 輸入 | 一組整數 |
| 輸出 | `true` 或 `false` |
| 要找的現象 | 任意兩個不同位置具有相同數值 |
| 是否需要找出位置 | 不需要，只需判斷是否存在 |
| 是否需要列出全部重複值 | 不需要 |
| 空輸入結果 | 沒有重複值，回傳 `false` |
| 一個元素 | 不可能重複，回傳 `false` |

這張表會直接影響程式：

- 因為只需判斷存在性，找到第一組重複便可提前回傳。
- 因為不需回傳位置，資料結構只要記錄「看過哪些值」。
- 因為空輸入和單一元素都沒有重複，可以自然走完整個流程後回傳 `false`。

分析不是額外的理論工作。它是在決定程式需要保存什麼資訊，以及何時可以停止。

## 3.2 第一步：移除故事背景

演算法題常用股票、城市、工作、機器人或遊戲包裝。故事可以幫助理解情境，但也可能讓人忽略底層資料模型。

例如：

> 某網站記錄每天的登入使用者 ID，請判斷是否有使用者在同一天重複登入。

移除故事後，可以寫成：

> 給定一組整數 ID，判斷是否存在重複值。

這個轉換很重要，因為演算法主要處理的是：

- 一組整數。
- 是否有重複值。

而不是網站、日期或登入畫面。

### 常見故事與資料模型

| 故事描述 | 可能的底層模型 |
|---|---|
| 每日價格、溫度或分數 | Array 或 Sequence |
| 城市與道路 | Graph |
| 資料夾與子資料夾 | Tree |
| 課程先修關係 | Directed Graph |
| 一段連續紀錄 | Subarray 或 Substring |
| 工作開始與結束時間 | Interval |
| 每次選或不選一個物品 | Subset Decision |

### 同一個故事不一定使用同一種演算法

以城市問題為例：

- 判斷兩個城市是否相連，重點是 Connectivity。
- 找最少經過幾條道路，可能是 BFS。
- 找總距離最短路徑，可能是 Dijkstra。
- 找連接所有城市的最低成本，可能是 Minimum Spanning Tree。

故事相同，但輸出要求不同，問題模型也不同。

## 3.3 第二步：整理輸入與輸出

### 輸入不只是型別

只寫「輸入是整數 Array」仍然不夠。還要確認：

- 元素數量。
- 每個元素的值域。
- 是否可能為空。
- 是否允許重複。
- 是否已排序。
- 是否允許修改輸入。

可以整理成：

```text
資料型別：整數 Array
元素數量：0 到 100000
元素範圍：-10^9 到 10^9
排序狀態：未排序
重複值：可能存在
允許修改輸入：否
```

### 輸出也不只是型別

以下要求雖然都和重複值有關，但需要的資料不同：

1. 是否有重複值。
2. 任意一個重複值是什麼。
3. 重複值出現在哪些 Index。
4. 所有重複值有哪些。
5. 每個數值出現幾次。

如果只需回答存在性，找到第一組重複便可停止。

如果要計算次數，就不能只使用 Set，通常需要 Map 保存 `數值 → 次數`。

### 無答案時如何表示

如果函式要回傳某個重複值，但可能沒有重複值，可以使用：

```cpp
std::optional<int>
```

在 C 中沒有標準 `optional`。常見方式是：

- 函式回傳成功或失敗的 `bool`。
- 使用輸出參數帶回答案。

例如：

```c
bool find_duplicate(const int values[], size_t length, int *result);
```

此函式可約定：

- 回傳 `true` 表示找到重複值，並將答案寫入 `*result`。
- 回傳 `false` 表示沒有答案，此時呼叫端不應讀取 `*result`。

這是語言介面的差異。演算法核心仍是尋找重複值。

## 3.4 第三步：記錄限制條件

限制條件會直接決定哪些方法可行。

### 元素數量影響時間複雜度

如果只有 20 個元素，檢查所有 Pair 通常足夠。

如果有 100,000 個元素，`O(n²)` 可能需要檢查接近一百億組 Pair，通常不可行。

### 值域影響資料結構

假設數值只可能是 0 到 100，可以使用固定大小 Array 記錄是否出現：

```cpp
std::array<bool, 101> seen{};
```

如果數值可能從 `-10^9` 到 `10^9`，固定配置整個值域便不合理，Hash Set 通常較合適。

### 排序狀態影響可用方法

已排序資料具有相鄰與單調性。例如重複值在排序後一定會相鄰，因此可以只比較相鄰元素。

未排序資料若要使用這個性質，需要先排序，而排序可能：

- 改變原始順序。
- 花費 `O(n log n)` 時間。
- 若不能修改輸入，需要建立副本。

### 負數可能破壞某些方法

部分 Sliding Window 解法依賴「加入正數只會讓總和增加」。如果資料包含負數，這項性質不再成立。

所以看到「連續區間」不能立刻套 Sliding Window，還要檢查數值條件。

## 3.5 第四步：找出候選答案

候選答案是演算法可能需要檢查的所有選項。

### 單一元素

找最大值時，每個元素都是候選答案。

```text
[7, 3, 9, 2]
候選：7、3、9、2
```

### Pair

Two Sum 的候選是所有不同 Index Pair。

```text
(0,1)、(0,2)、(0,3)、(1,2)、(1,3)、(2,3)
```

### 連續區間

對 `[1, 2, 3]`，非空連續區間包括：

```text
[1]
[2]
[3]
[1, 2]
[2, 3]
[1, 2, 3]
```

不包含 `[1, 3]`，因為它跳過中間的 `2`，不是連續區間。

### Subset

Subset 可以任意選或不選元素，不要求連續。例如 `[1, 3]` 是 `[1, 2, 3]` 的 Subset。

### 為什麼要先找候選空間

直接解法通常就是完整檢查候選答案。只有先知道候選有哪些，才知道：

- 直接解法是否完整。
- 工作量大約多少。
- 最佳化到底省掉什麼。

## 3.6 完整案例：找出重複值

### 問題規格

輸入：一組未排序整數。

輸出：如果任何數值出現超過一次，回傳 `true`；否則回傳 `false`。

範例：

```text
輸入：[4, 2, 7, 2]
輸出：true
原因：數字 2 出現兩次
```

### 人類直接解法

逐一比較所有不同位置的 Pair：

| 第一個位置 | 第二個位置 | 比較 | 是否相同 |
|---:|---:|---|---|
| 0 | 1 | `4` 和 `2` | 否 |
| 0 | 2 | `4` 和 `7` | 否 |
| 0 | 3 | `4` 和 `2` | 否 |
| 1 | 2 | `2` 和 `7` | 否 |
| 1 | 3 | `2` 和 `2` | 是，停止 |

### C++ 直接解法

```cpp
bool containsDuplicateBruteForce(const std::vector<int>& nums)
{
    // i 是第一個被選中的位置。
    for (int i = 0; i < static_cast<int>(nums.size()); ++i)
    {
        // j 從 i + 1 開始，避免比較同一位置，
        // 也避免重複比較順序相反的 Pair。
        for (int j = i + 1; j < static_cast<int>(nums.size()); ++j)
        {
            if (nums[i] == nums[j])
            {
                return true;
            }
        }
    }

    return false;
}
```

### 直接解法的問題

有 `n` 個元素時，最差需要檢查接近 `n² / 2` 組 Pair，時間複雜度為 `O(n²)`。

重複工作是：

> 每看到一個新數字，都重新掃描其他位置，判斷它以前是否出現。

可以改成直接記錄「以前看過哪些數字」。

### 程式需要保存什麼

| 資訊 | 用途 |
|---|---|
| 目前數字 `value` | 本輪正在判斷的數字 |
| 已看過的數字 `seen` | 判斷目前值是否曾出現 |

### C++ Hash Set 解法

```cpp
#include <unordered_set>
#include <vector>

bool containsDuplicate(const std::vector<int>& nums)
{
    // Set 只保存「哪些數字以前出現過」。
    // 本題不需要保存 Index 或出現次數。
    std::unordered_set<int> seen;

    for (int value : nums)
    {
        // contains(value) 為 true，表示 value 以前已經出現。
        if (seen.contains(value))
        {
            return true;
        }

        // 目前還沒有重複，因此把 value 記錄起來，
        // 讓後面的元素可以查詢。
        seen.insert(value);
    }

    return false;
}
```

### 逐輪執行

輸入：`[4, 2, 7, 2]`

| 輪次 | 目前數字 | 查詢前 `seen` | 是否已出現 | 本輪動作 |
|---:|---:|---|---|---|
| 1 | 4 | 空 | 否 | 插入 4 |
| 2 | 2 | `{4}` | 否 | 插入 2 |
| 3 | 7 | `{4, 2}` | 否 | 插入 7 |
| 4 | 2 | `{4, 2, 7}` | 是 | 回傳 `true` |

### 為什麼 Set 足夠

題目只問「是否存在重複值」，不要求：

- 重複值第一次出現在哪裡。
- 總共出現幾次。
- 列出所有重複值。

因此只記錄「看過或沒看過」就足夠。若題目要求次數，才需要 Map。

### C 語言補充

C 標準函式庫沒有 `std::unordered_set`。若值域很小，可以使用 Boolean Array：

```c
#include <stdbool.h>
#include <stddef.h>

bool contains_duplicate_small_range(
    const int values[],
    size_t length)
{
    // 假設所有值都介於 0 到 100。
    bool seen[101] = {false};

    for (size_t i = 0; i < length; ++i)
    {
        int value = values[i];

        if (seen[value])
        {
            return true;
        }

        seen[value] = true;
    }

    return false;
}
```

這個 C 版本有重要前置條件：所有值必須在 0 到 100 之間。若值可能是負數或範圍很大，就不能直接拿數值當 Array Index，需要：

- 先排序後比較相鄰元素。
- 自行實作 Hash Table。
- 使用專案中的 Hash Library。

C 的 Array 參數不會自動帶入長度，所以函式需要額外接收 `length`。演算法核心仍然是「保存以前看過的值」。

## 3.7 完整案例：連續區間和

### 問題

給定：

```text
nums = [2, 4, 1, 3]
```

求 Index 1 到 Index 3 的總和。

這段連續區間是：

```text
[4, 1, 3]
```

答案為：

```text
4 + 1 + 3 = 8
```

### 先確認區間語意

如果使用 Inclusive Interval `[left, right]`：

```text
left = 1
right = 3
包含 Index 1、2、3
```

如果使用 Half-open Interval `[left, right)`：

```text
left = 1
right = 4
包含 Index 1、2、3，不包含 Index 4
```

兩種表示都可使用，但整段程式必須保持一致。

### 直接解法

```cpp
long long rangeSum(
    const std::vector<int>& nums,
    int left,
    int right)
{
    long long sum = 0;

    // 本例使用 Inclusive Interval [left, right]。
    for (int i = left; i <= right; ++i)
    {
        sum += nums[i];
    }

    return sum;
}
```

### 需要先確認的前置條件

- `left >= 0`
- `right < nums.size()`
- `left <= right`

如果題目有很多次區間查詢，每次都重新加總會重複計算相同 Prefix。第 14 章會使用 Prefix Sum 改善這類問題。

### C 語言補充

C 版本的演算法相同，但必須另外傳入 Array 長度，才能檢查邊界：

```c
#include <stdbool.h>
#include <stddef.h>

bool range_sum(
    const int values[],
    size_t length,
    size_t left,
    size_t right,
    long long *result)
{
    if (left > right || right >= length || result == NULL)
    {
        return false;
    }

    long long sum = 0;

    for (size_t i = left; i <= right; ++i)
    {
        sum += values[i];
    }

    *result = sum;
    return true;
}
```

這裡使用 `bool` 回報函式是否成功，並透過 `long long *result` 輸出答案。這是 C 中常見的「回傳狀態 + 輸出參數」介面。

## 3.8 如何找出題目可利用的性質

### 排序

排序資料可提供：

- Binary Search。
- Two Pointers。
- 重複值相鄰。
- 某些條件下提早停止。

但排序可能改變原順序，也需要 `O(n log n)` 時間。

### 連續性

看到以下詞彙時，先確認是否要求連續：

- Subarray。
- Substring。
- Interval。
- 一段連續紀錄。

連續區間常和 Sliding Window、Prefix Sum 或 Difference Array 有關。

### 單調性

單調性表示某個條件只往一個方向變化。

例如已排序 Array 中，數值只會保持不變或變大。這讓 Binary Search 可以安全排除一半候選。

### 重複工作

直接解法中常見的重複工作：

| 重複工作 | 可能工具 |
|---|---|
| 一直查某個值是否存在 | Set、Map、Binary Search |
| 一直重新計算區間和 | Prefix Sum |
| 反覆計算相同 State | Memoization、DP |
| 一直尋找目前最小或最大值 | Heap |
| 檢查大量不可能候選 | 剪枝、排序、單調性 |

工具不是從題目關鍵字直接決定，而是用來減少某一項已辨識的重複工作。

## 3.9 如何使用反例檢查想法

反例是用來測試「我的推理是否總是成立」的小型資料。

### Sliding Window 加總

如果想用「總和太大就移動 Left」的方法，先加入負數測試：

```text
[5, -10, 8]
```

移除左端 `5` 後，總和反而可能變得更小或更大，原本的單調推理可能失效。

### Binary Search

如果判斷結果呈現：

```text
false, true, false, true
```

它不是單調分界，不能直接使用一般 Binary Search 找 First True。

### Greedy

如果每次選眼前最大值，試著設計一個情況，讓眼前最大值造成後面更差的結果。如果能找到，就表示尚未證明 Greedy 成立。

### Hash Set

如果題目要求輸出排序結果，Hash Set 不提供固定順序。查找雖然快，但輸出需求可能不適合。

## 3.10 建立自己的解題分析表

遇到新題目時，可以先填以下內容：

| 欄位 | 要回答的問題 |
|---|---|
| 問題摘要 | 移除故事後，真正要做什麼？ |
| 輸入 | 型別、大小、值域、排序、重複條件？ |
| 輸出 | 存在、數量、任意答案、全部答案或最佳答案？ |
| 邊界 | 空輸入、單元素、無答案時怎麼辦？ |
| 候選空間 | 元素、Pair、區間、Subset、Path 或答案範圍？ |
| 直接解法 | 最容易確認正確的方法是什麼？ |
| 重複工作 | 哪一部分被反覆執行？ |
| 可利用性質 | 排序、連續、單調、重複 State？ |
| 可能工具 | 哪個資料結構能減少已確認的瓶頸？ |
| 反例 | 什麼資料可能破壞目前想法？ |
| 驗證 | 如何用小型輸入和直接解法測試？ |

## 3.11 常見問題與判讀

| 現象 | 可能原因 | 第一輪檢查 |

| 排序後答案語意改變 | 沒確認原順序需求 | 是否保存原始 Index |
| 使用 Sliding Window 漏解 | 未檢查單調性 | 是否含負數或不可逆狀態 |

## 3.13 本章重點

1. 解題的第一步不是寫程式，而是整理問題規格。
2. 移除故事背景後，應能說出資料模型與輸出目標。
3. 輸入大小、值域、排序、重複值與修改限制都會影響方法。
4. 輸出要求決定程式需要保存哪些資訊。
5. 候選空間是直接解法的基礎。
6. 最佳化通常來自找出直接解法的重複工作。
7. 排序、連續性、單調性與重複 State 是常見可利用性質。
8. 反例可用來檢查方法的前置條件是否真的成立。
9. C++ 與 C 可以使用不同介面，但演算法核心應保持一致。
10. 固定的解題分析表可以降低漏看條件與盲目套模板的機率。
